# LLM Storytelling: Fine-Tuning Pythia-2.8b

Проект по полному циклу подготовки данных и тонкой настройке (full fine-tuning) языковой модели для генерации структурированных сказок по заданному названию.

## Описание проекта
Цель проекта — создать модель, способную генерировать связный фольклорный сюжет по одному лишь заголовку, а также продемонстрировать навыки Data Engineering (очистка, фильтрация, использование LLM-as-a-judge) и оптимизации обучения (Memory Management) на потребительском железе.

## Стек технологий
* **Python 3.12**, PyTorch 2.5.1
* **Hugging Face Ecosystem:** `transformers`, `datasets`
* **Оптимизация VRAM:** `bitsandbytes` (8-bit AdamW), Gradient Checkpointing, BF16/TF32
* **Локальный инференс (для EDA):** LM Studio (Qwen 7B Instruct)

## Структура проекта

* `EDA.ipynb` — Jupyter-ноутбук с полным циклом анализа, очистки и валидации данных.
* `distill.ipynb` — Jupyter-ноутбук преобразования данных, с использованием облачной LLM
* `train.py` — основной скрипт для запуска процесса fine-tuning с настройками экономии памяти.
* `config.py` — конфигурация параметров обучения и путей к данным.
* `utils.py` — вспомогательные функции (форматирование промптов, расчет перплексии).

## Процесс работы

### 1. Подготовка данных (Data Curation)
Исходными данными послужили 4 открытых датасета со сказками (включая народные сказки и тексты братьев Гримм). Сырые данные (CSV и TXT) прошли строгий пайплайн очистки:
* **Анализ сюжета (LLM-as-a-judge):** Использовалась локальная Qwen 7B Instruct для фильтрации обрывков и отбора только завершенных сюжетов.
* **Генерация заголовков:** Восстановление отсутствующих названий для текстов.
* **Дедупликация и токенизация:** Отфильтрованы дубликаты. Подсчет длины в токенах производился нативным токенизатором модели, чтобы отсеять тексты, превышающие окно контекста (оставлены сказки < 1900 токенов).
* Итоговый агрегированный датасет содержит **4355** размеченных сказок в формате `.jsonl`. 

### 2. Обучение модели
Процесс тонкой настройки (full fine-tuning) проводился со следующими вводными:
* **Базовая модель:** `EleutherAI/pythia-2.8b` (контекст 2048 токенов).
* **Железо:** Обучение проводилось локально на одной NVIDIA RTX 3090 (24 GB VRAM).
* **Оптимизация:** Для предотвращения Out Of Memory (OOM) при полном обновлении весов 2.8B параметров использовался квантованный оптимизатор `adamw_bnb_8bit` и `gradient_checkpointing`.
* **Результат:** Обучение было остановлено на ранней стадии (2 эпохи) на основе мониторинга `eval_loss` для предотвращения переобучения (overfitting).

### 3. Известные ограничения (Known Limitations)
При анализе сгенерированных текстов были выявлены следующие особенности:
1. **Стилистический сдвиг (Data Bias):** Из-за высокой доли неадаптированных фольклорных текстов и сказок братьев Гримм в обучающей выборке, модель склонна генерировать довольно мрачные и суровые сюжеты.
2. **Завершение генерации:** При текущем объеме обучающей выборки модели не всегда удается надежно связать логическое завершение сюжета с генерацией `eos_token`. В некоторых случаях генерация упирается в лимит токенов контекстного окна до того, как история будет закончена.
